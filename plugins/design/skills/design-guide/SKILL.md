# Design guide

This guide only routes. Before you answer or act, load the matching skill with the skill
tool, by id, in this same turn, and every other row the task spans. Answer from the loaded
skill, not from this table.

| Situation | Load skill |
| --- | --- |
| Write or lint a DESIGN.md, document the design | `design-md` |
| What tokens, scales and primitives does this project use; before UI work | `design-system-audit` |
| Wireframe, mockup, prototype or deck request: route to the right producer | `design-prototype` |
| Mock up a dialog or draw a wireframe as inline SVG (fenced `wireloom` block) | `wireloom` |
| Adding or changing animation: durations, easings, reduced motion | `motion-design` |
| Writing or reviewing UX copy: errors, empty states, CTAs, confirmations, onboarding | `ui-microcopy` |
| Review this UI: ARIA snapshot, computed styles, keyboard walk | `ui-review` |
| Is this accessible, check accessibility, WCAG 2.2 AA | `accessibility-audit` |
| Critiquing or building a rendered UI: generated-UI tells, missing interaction states | `design-no-slop` |
| Any claim about a rendered UI: cite ARIA, computed style or screenshot plus viewport | `design-evidence` |
| Styling a component or editing tokens | `design-token-discipline` |
| Passing component props or writing Storybook stories | `design-component-truth` |
| Before routing to an upstream design skill or CLI | `design-upstream-preflight` |
